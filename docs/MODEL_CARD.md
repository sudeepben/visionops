# Model card: VisionOps PCB defect detector

## Model
- **Architecture:** Ultralytics YOLO11n (COCO-pretrained), fine-tuned for PCB defect detection.
- **Training config:** `configs/baseline.yaml` (seeded; exact arguments, library versions and GPU are
  recorded in `reports/runs/<name>.json`).
- **Input:** RGB image, letterboxed to `imgsz` (default 640).
- **Output:** axis-aligned boxes with class and confidence.

## Intended use
Portfolio / research demonstration of an inspection workflow: detect candidate PCB defects,
surface failure modes, and prioritise data for human review. **Not validated for production
quality control.** A production system would need data from the target line, cameras and
lighting, plus agreed acceptance criteria.

## Data
- Source: [PCB Defect Detection on Roboflow Universe](https://universe.roboflow.com/pcbdataset/pcb-defect-detection-9ewqw)
  (workspace `pcbdataset`), licence **CC BY 4.0** as listed on the dataset page.
- Class names, split sizes and label checks are in `reports/data_validation.json` and in the results below.
- If the export has no test split, `visionops.data.prepare` carves one from train, grouped by
  source image so Roboflow-augmented copies cannot leak across splits. The test split is never
  used for training, model selection or curation decisions.

## Evaluation
- Held-out test split; mAP@50, mAP@50-95, precision and recall from the Ultralytics validator.
- Sample-level analysis at a fixed operating point (conf >= 0.25, IoU >= 0.5); matching rules are
  documented in `visionops/matching.py` and the README.

## Limitations and risks
- Small, public dataset; images and defect types may not represent real manufacturing variation
  (boards, cameras, lighting, defect sizes).
- PCB defects are small. At 640 px input, the smallest defects may be under-resolved.
- Results come from a single training seed unless stated otherwise. Small metric differences
  between runs may be noise.
- Review flags come from model-label disagreement. They are priorities for a human reviewer and do
  not prove a label is wrong. Training-set predictions are in-sample, which under-counts errors.
- GPU training is not bit-for-bit deterministic even with fixed seeds.
